# 诊断字典与报告协议

> 用途：你在公司内网跑对局后，**用一句话**把现象发给开发者；本文件把「现象」映射到
> 「模块 → 事件码 → 可调参数」，让改动精准命中（方案 §4.4）。
> 事件码定义见 `src/future_war/observability/events.py`；参数见 `config/default.json`。

---

## 一、工作流（回顾）

```
开发者 push ──▶ 你公司 git pull ──▶ 内网平台跑对战 ──▶ 你读固定日志
   ▲                                                      │
   └──────────── 你一句话反馈 ◀──────────────────────────┘
```

- 数据不出公司：你只需发**现象 + 证据码**，无需外传原始日志。
- 每次迭代**只动一处**（one knob per iteration），便于归因与回滚。

---

## 二、日志格式与查看

每回合一行，格式固定：

```
<round> <phase> <TAG> <CODE> <message> <k=v ...>
0085 N [ECON]   E-01 collect worker=10010 target=stone@(4,24) got=1 gold=20
0120 N [COMBAT] C-03 attack weapon=10040 ctrl=10011 target=(4,5) dmg=20 cd=3
0130 - [METRIC] M-01 metric gold=45 kills=6 score=280 baseHP=1500 rolesAlive=7 errors=0
```

- `phase`：`D` 白天 / `N` 夜晚 / `-` 非回合内（如启动、汇总）。
- 每回合**必有一行** `[METRIC] M-01`，字段固定，便于你方内部大模型直接归纳。
- 文件：`logs/<match_name>_<utc>_<pid>.log`（事件流）；同名 `.jsonl` 是回放事实源。

**常用查看命令**（把 `logs/xxx.log` 换成实际文件）：

```bash
grep '\[METRIC\] M-01' logs/*.log          # 每回合指标（看趋势最快）
grep '\[ERROR\]' logs/*.log                # 所有错误
grep -E 'N-0[23]' logs/*.log               # 工人卡住/绕行
grep -E 'C-0[125]' logs/*.log              # 武器不开火/基地掉血
grep -E 'E-0[145]' logs/*.log              # 采集/升级/金币
tail -50 logs/*.log                        # 最近 50 行
```

## 三、一句话报告模板

```
[版本=<commit>][第N天/昼或夜][现象=<...>][证据=<TAG CODE>]
```

示例：

```
版本=3e7470b 第3天夜 基地掉到400 只建了1座武器 证据=[BUILD]B-02×3 [COMBAT]C-05×12
版本=3e7470b 第2天昼 工人10012卡在(5,5)反复绕 证据=[NAV]N-02×40
版本=3e7470b 全 局 LLM报errorCode5 证据=[LLM]L-01×2
```

> 不确定版本时，看启动行 `[INIT] I-01 ... stamp=<commit> / <config-hash> / <profile>`。

## 四、诊断表（现象 → 模块 → 事件码 → 参数）

| 现象（你这样描述） | 模块 | 事件码 | 可调参数 | 说明 |
| --- | --- | --- | --- | --- |
| 工人原地打转 / 空转 | NAV | `N-02` `N-03` | `nav.replan_interval` `nav.collision_avoidance` | 目标不可达或反复绕行 |
| 采集效率低、跑图多 | NAV/ECON | `E-05` `N-04` | `nav.replan_interval` `economy.vendor_peak_window` | 采矿路线/重规划频率 |
| 金币不足、升级慢 | ECON | `E-04` | `economy.sell_hold_ratio` `economy.budget_ratios` `economy.emergency_reserve` | 卖出时机与预算分配 |
| 卖矿时机差、价格低 | ECON | `E-02` `E-06` | `economy.vendor_peak_window` `economy.sell_hold_ratio` | 等峰值再卖 |
| 武器夜里不开火 | COMBAT | `C-01` `C-02` | `combat.controller_pairing` `combat.target_priority` `combat.rocket_aoe_threshold` | 无合法目标或无人操控 |
| 击杀太少 / 伤害浪费 | COMBAT | `C-03` `C-04` `C-06` | `combat.target_priority` `combat.overkill_avoidance` | 目标分配与防溢出 |
| 基地夜里掉血快 | COMBAT/BUILD | `C-05` `B-02` | `defense.base_hp_alert_ratio` `defense.boss_emergency_rounds` `defense.wall_repair_threshold` `build.chokepoint_count` | 布局/回防/修墙 |
| 只建了很少武器 / 建造失败 | BUILD | `B-01` `B-02` | `build.order` `build.day1_max_weapons` `build.weapon_mix` | 建造顺序与配比 |
| 围墙挡自己人 / 迷宫太深 | BUILD | `B-02` `N-02` | `build.wall_labyrinth_depth` | 浅迷宫而非整圈 |
| 任务老超时 / 反复放弃 | TASK | `T-03` | `tasks.timeout_margin_rounds` `tasks.self_evolution_enabled` | 提前放弃余量 |
| 寻宝召唤失败 | TREASURE | `R-02` `R-03` | `tasks.treasure_probe_cap` `tasks.treasure_enabled` | 地点/时间/物品三要素 |
| LLM 报 errorCode 5 / 配额超限 | LLM | `L-01` | `llm.daily_quota` `llm.free_window_enabled` | 每游戏日 3 次（任务期免费） |
| 沙盒命令超时 / 输出被截断 | SANDBOX | `S-02` `S-03` | （代码修复：拆分命令 / 落文件再读） | 15s 上限、64KB 截断 |
| 服务无响应 / 异常 | ERROR/ANOMALY | `X-01` `X-02` `X-06` `X-99` | `features.replay_enabled` `features.metric_line_enabled` `log.level` | 进程绝不崩溃（§八） |
| 日志缺行 / 想看得更细 | DIGEST/INIT | `D-01` `M-01` `I-01` | `log.level` `log.trace_enabled` `features.metric_line_enabled` | 提高级别到 DECISION/TRACE |
| 敌方推家 / 压力大 | OPP | `O-03` | `offense.enabled` `defense.*` | 威胁识别与应对 |
| 想更激进进攻 | OFFENSE | `O-03` `C-03` | `offense.enabled` `offense.base_snipe_enabled` `offense.summon_harass_enabled` `offense.all_in_score_gap` | 施压/骚扰/推家 |

## 七、稳定性约定

- 事件码与配置键**只增不改、不删除**；新增码/键时同步更新本文件。
- `tests/test_diagnosis_dictionary.py` 自动校验：本文件引用的每个事件码存在于
  `events.py`、每个配置键存在于 `config/default.json`，防止文档漂移。
